# Verdent 用量扩展

此扩展集成在 Token Monitor 的 Electron 应用中：设置中的 **Verdent** 折叠项（与常规、主画面、多设备同步同级）。该项仅保留启用开关、状态和“管理账号、采集与历史”按钮；账号、登录、采集设置及详细统计集中在管理页。Usage Dashboard 右上角的 **Verdent** 也可打开管理页。当前上游没有通用插件 SDK；实现通过主进程生命周期、受限 IPC 和独立应用窗口接入。无需新依赖，不需要 CSV / JSON 导入。

## Windows 安装与使用

当前工作区已经安装依赖后，可直接双击根目录的 `start-token-monitor.cmd`，打开 Token Monitor 主窗口，无需先打开终端。脚本从自身目录启动，沿用 `tmp/verdent-desktop/` 的开发实例登录态与统计。需要同时打开登录窗口时，执行 `.\start-token-monitor.cmd --login`；只检查启动条件可执行 `.\start-token-monitor.cmd --check`。该快捷入口与下面的 `npm run verdent:dev` 使用相同实例；`npm start` 使用另一个 userData 目录。

在仓库根目录使用 Node.js 22.15+（推荐 24）执行 `npm ci`，然后 `npm start`。与上游相同，首次启动会准备其固定版本的 Tokscale。需要本地安装包时执行 `npm run dist:win`，不会推送或发布。

也可以用 `npm run verdent:dev` 启动真实应用的隔离开发实例（加 `-- --login` 会自动打开登录窗口），数据保存在被 Git 忽略的 `tmp/verdent-desktop/`。它与正常启动使用不同的本机会话，切换启动方式需要在各自实例重新登录。

1. 点击 Token Monitor 的设置按钮，展开 **Verdent**，打开“采集 Verdent 用量”。默认关闭，不发送任何请求。
2. 点击“管理账号、采集与历史”，填写本地标签，添加账号槽。每个账号槽有独立 Chromium partition。标签仅用于本机识别，不是认证凭据。
3. 点击“登录 / 重新登录”，在独立的 Verdent 官网窗口自行完成登录。已识别的成功 OAuth JSON 回调会自动返回 Dashboard；若仍停在 Verdent 的回调页，点击用量窗口的“完成登录并刷新”返回 Dashboard 并实际核对身份、读取用量。JSON 的 `data: null` 本身不代表身份已验证。无需在聊天或设置中粘贴 Cookie、密码、令牌。外部 Chrome / Edge 的登录态不共享。
4. 采集始终覆盖服务器仍保留的最近 3 个日历月，起点按系统本地日期倒推并在月末截齐，结束时间固定为本次采集开始的秒。首次刷新补齐全部分页；点击“刷新用量”增量更新并复用本机快照，点击“回溯最近 3 个月”强制重新读取全部分页。管理页可配置自动刷新间隔。主页的今天、本月、总计等选项只筛选显示，不改变采集范围。刷新期间显示两轮读取及分页进度。
5. 查看输入、输出、缓存读取、缓存创建、原始总 Token 和 Credits，以及模型、功能、子代理、业务子类型、平台、来源分组。也可按首次创建日期（系统本地时间）或首次创建时间（秒）分组。未知名称原样显示，空子代理显示“（空值）”。
6. 历史保存当前在线范围快照、已过在线保留期的本地归档，以及旧版本留下的范围快照。点击日期仅查看，不改变采集。滚动在线快照成功后原子替换，落在新范围之外的旧记录同时归档；所有相同记录均保留。重叠范围按最新结果计算，绝不直接相加。

自动采集间隔按整数秒配置（1–3600 秒），默认 30 秒；填 0 仅启动与手动。每轮结束后等待设定间隔再检查，不并发、不积压定时任务；短间隔不保证服务端即时入账。持久化和兼容 IPC 继续使用 `intervalMinutes`，允许秒数除以 60 后的小数，旧分钟配置无需改写；旧版本配置保留原间隔、账号和历史，采集策略迁移为最近 3 个月，旧固定日期不再限制采集。在线范围在每次采集时按系统本地时间重新计算；超出在线保留期的本地已采集记录持续保留，尚未保存且已被服务器删除的数据无法恢复。只要启用 Verdent，每次手动启动 Token Monitor 都立即检测一次，包括关闭定时采集的情况。定时采集开启时，休眠恢复会补刷已到期的数据；未到期的缓存等待剩余间隔。主窗口与浮动面板的普通用量刷新也会异步触发 Verdent，原有刷新完成提示不代表 Verdent 已完成，可在 Verdent 设置中查看进度、错误及下次采集时间。两处配置界面共享同一主进程状态，采集不会并发重复执行。应用退出后停止采集，关闭用量窗口不影响定时器；不配置开机自启、不安装后台服务，应用由用户手动启动。登录失效会暂停自动请求，手动重新登录并刷新后恢复。清除本地登录态会清除该账号槽的 Chromium storage/cookies/cache，保留用量历史。

## 统计与边界

生产请求沿用已验证的 Dashboard 页面 `fetch` + `credentials: 'include'`，固定 `team_id: "0"`、`consume_type: ""`、`page_size: 10`。这些值的其他业务含义或可选值未验证，不提供团队／类型切换。日期按系统本地日历换算成秒级时间；生产采集从三个月前当天零点到本次采集开始秒，诊断单日查询到次日零点前一秒。日期转换由离线测试覆盖。

官网公开 Dashboard bundle 声明的 `GET https://login.verdent.ai/passport/inner/user/trackinfo` 是身份验证候选接口：仅接受 `data.user_id`，哈希后隔离账号用量；采集前后核对，身份缺失或变化时失败关闭。该端点在 Electron 中的可用性必须随用户登录实测，不能仅根据公开源码宣称验证。账号槽隔离浏览器状态；同槽内更换真实账号也以不同哈希隔离快照，不合并。

首次采集顺序读取所有分页，每页间隔至少 350ms，校验 HTTP、errCode、结构、页码、分页大小、total 和每页条数。固定查询结束时间，两次读取进行保留重复数量的内容比较；total 或内容漂移最多重试一次，重试时强制完整读取。持续写入时可能失败，此时保留最后成功结果。

后续启动、手动及定时刷新按真实账号隔离复用已有快照。历史和新读到的前缀须按首次创建时间倒序；在旧时间游标以下匹配连续 20 条记录的全部字段及重复数量，按新旧 total 对齐位置，且不在同秒记录组中间截断，才停止读取旧页并复用本地尾部。两轮读取仍需一致。范围向前滚动时，已离开在线范围的缓存记录不再参与在线分页对齐，但会保留为本地归档；更早范围扩展、账号切换、total 减少、顺序或匹配异常均退回完整读取。新的重叠快照可能修正旧历史时，也先完整复核。

成功结果继续原子保存完整记录及上次完整核对时间，重启后仍可复用。正常采集不因超过 24 小时而重新读取全量；点击“回溯最近 3 个月”可以完整复核在线范围。**服务端未提供不可变记录或事务快照保证：未读取的旧尾部如被修改，需等完整复核才能补齐**；两轮前缀匹配不能证明旧历史永远不变。该策略按用户要求用历史快照换取刷新速度，不把时间戳当唯一 ID。

所需分页、缓存衔接和身份核对成功后，使用现有 `writePrivateJsonAtomic()` 原子覆盖对应范围，写盘成功后才发布新状态。采集、取消、超时、登录、字段或写盘失败不会覆盖原成功快照。字段完全相同的记录与同秒记录均保留，排序指纹仅用于比较，不用于去重。

分类不一致时，程序保留本次异常记录的原始已知字段供界面检查，**不更新成功快照**，不会改写 total_tokens 或猜测缺失分类。异常候选仅留在本次进程内；成功快照持久化已知原字段（不保存未经白名单审查的新字段）。

模型分组按 `model_name` 与 Eco 标记区分：仅 `business_sub_type === "eco_mode"` 的显示名追加 `[eco]`，同名的非 Eco 模型保持原名。主界面、工具展开、模型列表、历史图表及管理页采用相同分组；模型别名也保留 Eco 后缀。原始 `model_name` 与业务类型字段不改写，不根据零 Credits 猜测 Eco。列表不添加日期归属或账号说明副标题。

Credits 独立于货币金额，0 正常显示，不使用模型公开价格估算实际账单。记录条数不是调用／请求次数。按用户选定的口径，时间分组采用 `first_create_time`，以 系统时区 划分日期；秒级分组同时显示系统本地时间和原始时间戳。它是时间归属依据，不作为唯一记录 ID，同秒和完全相同的记录均保留并计入分组。此口径不要求先证明服务端按消费时间过滤。接口未证实稳定记录 ID、project_id 或 session_id，因此不支持项目／会话关联。

启用后，当前账号的本机已采集历史加入 Electron 主页总 Token，与 Codex 等工具并列。今天、本月、总计及周／最近 7 天／最近 30 天使用对应日期范围；工具与模型显示 Token、缓存与输出分类以及 Credits，趋势、热力图、活跃日、连续日期及峰值包含可归属的 Token。Credits 在工具行独立显示，在总花费旁和 Dashboard 中单列；同一模型同时用于其他工具时分别显示货币与 Credits，不做兑换。设置使用与其他条目一致的单色线条图标。

已有范围快照保持实际查询的秒级起止时间，不因系统时区改变而重写；显示汇总按 `first_create_time` 的系统本地时间日期拆分，同一账号的重叠时间范围取更新时间较新的完整快照。空快照也会覆盖对应日期，重复刷新不累加，同秒和完全相同记录的数量完整保留。管理页显示覆盖日期及已采集天数，范围中可能有缺口；图表从最早已保存记录开始，尚未采集日期不声称为零。首次采集或手动回溯补齐服务器保留期内的历史；窗口向前移动或系统时钟回退时，旧快照落在新范围之外的记录按原成功更新时间归档，与新快照一并原子写入。归档仍参与主页日期筛选与总计。切换系统时区后，旧范围边界可能落在一天中间，这些日期标为部分覆盖；已读记录仍计入总量。新查询按系统本地日历边界计算，支持夏令时造成的非 24 小时日期。新快照不保存固定属地或时区名称；时区仅用于本机日期换算，不发送给用量接口、同步或导出。含范围外首次创建时间的快照保留在管理页，并提示暂未计入主页，防止误归属。

设备视图以独立的 Verdent 账号行展示，不把账号用量归给任何物理设备；不生成项目、会话、请求次数、上下文、运行状态、时长或速度数据。Verdent 不进入 Tokscale 原始设备记录、通用导出、Hub 或 iCloud 同步：在多设备汇总完成之后，本机显示层只加一次当前账号数据。关闭开关即从显示汇总移除，历史与登录态保留。已有通用导出是序列化输出，不是本扩展的导入通道。

## 本地数据与凭据

开发快捷入口的实际数据根目录为 `tmp/verdent-desktop/`；下文的 `userData` 表示应用数据根目录，不是待提交的源码目录。账号、历史与登录态会保留在本机，公开 Fork 只提交源码。`.gitignore` 排除开发数据及常见凭据、快照、Chromium 会话路径；`npm run verify:privacy`（也包含在 `npm run verify` 和测试中）检查可提交文件与暂存内容中的这些路径及序列化账号指纹。它是针对已知格式的防误提交检查，不替代发布前的内容审查。公开测试只能使用合成数据；不要上传整个工作区压缩包或应用数据目录。

- `userData/verdent-usage.json`：开关、间隔、范围策略及兼容保留的旧日期、本地账号标签、随机账号槽 UUID、账号 ID 的 SHA-256 指纹、原始用量字段及成功更新时间。没有 Cookie、密码或令牌。文件损坏／结构不支持时拒绝覆盖。
- `userData/Partitions/verdent-<UUID>/`：Electron / Chromium 管理的网站登录状态；与普通浏览器、Token Monitor 主窗口及其他账号槽隔离。这是浏览器会话存储，不是提供方自行导出的凭据文件。Windows 使用当前用户的本机访问权限；本机同用户进程可能访问会话，请勿把 userData 当成可分享的导出目录。
- 远程登录页无 Node、无 preload、启用 sandbox/contextIsolation/webSecurity；登录窗口及 OAuth 弹窗不获得应用 IPC。拒绝非 HTTPS 导航、下载及额外权限。主进程只向受信任的本地主窗口与 Verdent 用量页面的顶层 frame 暴露有限命令和白名单统计字段，绝不返回 Cookie/headers/localStorage。
- 不记录原始响应、服务端 errMsg、请求头或异常对象。网络错误显示固定文案，未知 errCode 只显示数字。凭据不进入 Git、日志、导出或同步。

## 验证

离线测试：`node --test tests/electron/verdent.test.js tests/electron/verdentBrowserSession.test.js tests/electron/verdentHistory.test.js tests/electron/verdentIncremental.test.js`；完整检查：`npm run verify`；真实应用窗口烟雾检查：`npm run verify:verdent:electron`（自动使用独立的合成账号槽，不调用 Verdent；结果 `tmp/verdent-smoke-result.json`）。加 `-- --screenshot` 可保存 `tmp/verdent-ui.png`，需要可用的 Windows 桌面合成器；捕获失败会明确报错并使该命令失败。测试夹具全部为人工合成数据，不包含个人账户历史、真实用量样本或真实标识符。

`npm run verify:verdent:login` 在真实 Electron 中拦截网络并提供合成的 JSON 回调、身份和用量响应，验证回调恢复、页面请求和快照落盘；报告在 `tmp/verdent-login-smoke-result.json`。它不访问真实 Google / Verdent 账号，不能代替真实登录验收。页面加载、浏览器会话保存和用量文件写盘分别报告错误，只有实际写盘失败才提示文件权限问题；所有失败均保留最后成功统计。

采集支持 `https://www.verdent.ai` 与 `https://verdent.ai`，包括 `/zh-CN/dashboard` 等本地化路径，并检查同一账号槽的 OAuth 子窗口。页面已就绪但资源仍在加载时不判为登录失效；导航期间等待页面就绪，超时单独报告。登录状态仍以身份和用量接口为准。界面只显示所选官网的 origin，不显示可能包含凭据的查询参数。

真实验证流程：

1. 新账号槽登录，点击“回溯最近 3 个月”，确认全部分页成功，并核对官网相同筛选的合计；记录最后成功时间及条数。
2. 未新增用量时重复刷新，比较总量、条数及内容指纹。正常产生用量后再刷新，比较新旧原始记录多重集合，才能判断新增记录还是聚合更新；不能从 total 推断调用数。
3. 在历史中选择完整的 7 天，再点击“验证采集范围与逐日合计（7 天）”；未选择历史时默认验证最近 7 天。程序读取两次完整周范围、七个单日、再次周范围，以及同 partition 的 Electron `session.fetch`。界面显示稳定性、各字段合计与后台请求结果；诊断结果不写入用量历史。周范围不稳定时，即使单日合计相等，也不构成日期语义验证。
4. 日期端点是否包含边界、首次创建时间与消费时间关系，需要有边界附近的真实记录，再进行相邻秒区间对照。单周相等不足以证明永久适用；当前日期图表只表示用户选定的首次创建时间归属，不宣称是精确的消费发生日。
5. 退出并重启同一开发／安装实例，验证会话持久化。清除登录态再刷新应保留历史并提示登录；重新登录验证恢复。新账号槽应看不到旧槽用量；同槽换账号后不应混合不同身份。

公开网站 bundle 另声明了 `credits_details_chart`，但未确认它包含稳定记录／项目／会话 ID，也未把它用作统计权威。当前支持的用量接口是 `credits_details`。

实际验证记录见本目录的 `verdent-verification.md`；未完成项目必须保留为待实测，不可把离线测试或官网浏览器证据写成 Electron 登录成功。
